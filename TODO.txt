--- ЦЕЛЬ ПРОЕКТА ---

Создать лёгкое десктопное приложение для быстрой фиксации
проведённых занятий и последующего экспорта данных в
Яндекс.Таблицы (HTML-копирование). Приложение должно быть
простым, локальным и решать конкретную боль: избавить
от рутины при переносе данных в журнал.

! 1. ПАПКА ДАННЫХ — ВЫБОР ПОЛЬЗОВАТЕЛЕМ
     Проблема:
       - data_dir() использует CARGO_MANIFEST_DIR — путь зашит
         в бинарник на этапе компиляции.
       - У пользователя этой папки НЕТ → приложение сломается.
       - Портативная версия не работает (нет прав на запись).
     Решение:
       - При первом запуске — пользователь выбирает папку данных.
       - Выбранный путь сохраняется в системный конфиг
         (%APPDATA%\simple-hot_on_the_heels-notebook\config.json).
       - Fallback: если конфига нет — использовать AppData.
       - В настройках — кнопка «Папка данных» + «Открыть папку».
     Примеры:
       - TauriTavern (tauritavern-runtime.json в системной папке)
       - Obsidian (Vault Switcher)
       - Trilium (выбор папки данных в UI)
     Добавить крейт dirs для поиска системных папок.

! 2. НАПОМИНАЛКА О ЗАНЯТИИ
     Идея:
       - Приложение работает в трее (иконка рядом с часами).
       - После занятия по расписанию — всплывает уведомление:
         «Занятие "Группа А" прошло. Записать?»
       - Кнопка [Записать] → открывает форму с выбранной группой.
     Требуется:
       - Tauri Tray (иконка в трее).
       - tauri-plugin-notification (системные уведомления).
       - Сворачивание в трей (не закрывать приложение).
       - Настройки: вкл/выкл + время напоминания для группы.
     НЕ делать расписание на неделю — только простые напоминания.
     Это отдельный этап — после папки данных.

     ПОДРОБНОЕ ОПИСАНИЕ ЛОГИКИ:
     См. docs-tray-notifications.txt

     Настройка tray в tauri.conf.json:
       "trayIcon": {
         "iconPath": "icons/icon.png",
         "iconAsTemplate": true
       }

==================================================================
  НЕ РАБОТАЕТ / ОСОБЕННОСТИ
==================================================================

1. Спиннер при удалении виден не всегда.
   Причина: строка исчезает из DOM быстрее, чем Svelte
   успевает отрисовать спиннер.
   Что пробовали:
     - withMinLoading (400 мс) — не помогло.
     - Локальный minDelay — не помогло.
   Вывод: удаление проходит мгновенно, спиннер не успевает.
   Это НЕ баг — это особенность быстрой операции.
   Оставлено как есть.

2. SQLite не используется.
   Причина: для текущего объёма данных хватает txt-файлов.
   Решение: если данных станет много — перейти на SQLite.

3. Данные хранятся в открытом виде.

4. ФОРМАТ ДАТЫ — РАЗНЫЙ В ХРАНЕНИИ И UI
   Решение:
     - В файлах, JSON, Rust — ISO 8601: YYYY-MM-DD.
       Это стандарт, сортируется как строка, переносим.
     - В UI (список занятий, просмотр) — DD.MM.YYYY.
       Это привычнее пользователю.
     - Между ними — функция formatDate() в utils/formatDate.ts.
   Почему так:
     - Сортировка строк "2026-10-14" < "2026-10-14" — правильная.
     - С "14.10.2026" и "14.10.2026" — сентябрь оказался бы
       после октября, потому что "29" > "02" как строка.
     - ISO 8601 — мировой стандарт для хранения дат в тексте.
   НЕ менять формат в файлах — это сломает сортировку.

5.
   Причина: txt-файлы, нет шифрования.
   Решение: если понадобится — добавить шифрование.
   Пока — пользователь предупреждён (README, INSTALL, футер).
